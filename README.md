# しらつめ · Shiratsume

以模型为主角的静态交互展示 demo。配色以 `#B7BB5A`、奶白和深灰为基础，展示首页视频、四叶草动效、章节导航和中日双语切换。

源码仓库：[Amubis/shiratsumePage](https://github.com/Amubis/shiratsumePage)。GitHub Pages 部署成功后可访问 [little clover garden](https://amubis.github.io/shiratsumePage/)，部署状态以仓库 Actions 为准。

## 当前版本

- 首页短视频随机播放，片段之间交叉淡入；支持清晰观看、返回首页与暂停。
- 首页文字、顶部导航和四叶草依序出现；文字使用干净的前景色与随图案移动的局部反色，不附加描边或文字阴影。
- 四叶草采用较短的自然摆动周期，呈现轻微风感；悬停导航时有旋转和泡泡装饰。
- 全页面使用原生自然滚动，接近章节边界时轻吸附；取消累计一屏滚动量和强制翻页。长章节可自由浏览，竖屏先采用紧凑导航和默认适配方案。
- 支持中文／日语，以及独立的模型主题配置。第二套模型只用于主题切换预览，不代表另一模型的真实素材。
- 响应系统“减少动态效果”设置，媒体播放失败时以封面和播放入口兜底。

这仍是展示和交互验证版本：真实照片相册、EXIF 批量整理、账号登录和上传管理后台尚未接入，不会把示例数据写入任何远端数据库。

## 本地运行

需要 Node.js 22 或更新版本。项目不依赖第三方 npm 包，无需 `npm install`。

```sh
npm run dev
```

在浏览器中访问命令输出的网址。开发源码使用 ES module，通过上述命令预览。

```sh
npm run test
npm run build
```

`dist/` 是可部署的静态网页目录，构建产物不进入源码仓库。构建后也可以直接打开 `dist/index.html` 查看：脚本已打包，无需额外 HTTP 服务。部分浏览器对本地媒体的限制仍可能影响自动播放，届时可点播放按钮或使用开发服务器。

部署时应保留整个目录结构；资源采用相对路径，以适配 GitHub 项目站点的仓库子路径。

## GitHub Pages

无需购买服务器，也无需让自己的电脑持续开机。

1. 在你自己的 GitHub 账号下创建一个源码仓库，并将此项目的内容放到仓库根目录。
2. 默认分支使用 `main`；若使用其他分支，相应修改 `.github/workflows/pages.yml` 中的触发分支。
3. 进入仓库 **Settings → Pages → Build and deployment → Source**，选择 **GitHub Actions**。
4. 推送 `main` 后，或在 **Actions → Deploy demo to GitHub Pages → Run workflow** 手动触发。
5. 等工作流完成，从部署记录打开 GitHub Pages 网址。已有域名可以之后再绑定。

工作流会使用 Node.js 22 运行测试、构建，再将 `dist/` 上传到 Pages。没有外部运行时服务、数据库密码或需要填入的部署 token；工作流使用仓库自带的临时权限。

GitHub Pages 是否支持私有源码仓库，取决于账号计划和组织设置。项目不会替你把仓库改为公开；如果选择公开仓库，请只放准备公开的源代码和素材。公开网页中的媒体仍可被访客获取。

## 本轮验证

自动测试涵盖原生滚动不被拦截、程序定位取消、长章节与弹层行为、视频播放失败与旧模型异步隔离、共享蒙版坐标变换、固定泡泡槽位、随机配色边界和中日文覆盖；构建另外检查 JavaScript 语法与静态资源路径。

本轮已在 Chromium 的 1440×900 桌面和 390×844 手机视口检查：无 JavaScript 页面错误或横向溢出；蒙版内的第二页预览、转场后的定位与清理、原生滚轮跟随均通过。Safari 蒙版和真实触控设备仍需另行验证。本轮只向这个 demo 仓库发布，未改动既有网站。

### 0.1.1 视频播放排查

- HTML 自带可手动播放的原生视频；脚本成功后接管主层并补第二层，不重复创建第三个播放器。
- 页面明确显示加载、暂停、自动播放受限、加载超时或播放失败，并提供播放重试和单独打开视频入口。减少动态设置会保留手动播放。
- 加载超过 8 秒会提示超时，迟到的播放成功仍可恢复；旧请求不会覆盖暂停、重试和模型切换后的新状态。
- 打包后的脚本和样式使用内容指纹，避免新页面继续读取浏览器缓存里的旧脚本。
- 模拟 DOM 启动检查确认了脚本可运行并启动两层播放器；这不能替代真实浏览器的媒体解码测试。

若仍无法播放，请记录页面显示的状态、浏览器名称，以及“单独打开视频”是否可播放。若所有主题和语言按钮也不响应，优先检查浏览器控制台中的脚本加载错误。

### 0.2 视觉与交互调整

- 按最新选择改为全平台自然滚动与章节边界轻吸附，移除滚动量累计、强制翻屏和触摸结束后的强制定位。点击导航仍平滑定位，新的滚动输入可立即打断。
- 探索入口先轻放大约 240ms，再收拢约 460ms，保留约 170ms 的小点停顿，然后用约 1.2 秒逐渐加速展开。
- 第二屏背景色与展开的四叶草使用同一个轮廓，只在图形内部逐渐显现；覆盖视窗后才显示第二屏内容，避免背景色先在全屏淡入。

- 移除全局文字描边和文字阴影，首页以黑色文字为基础；共享图形蒙版只切换交叠区域的前景色，副本不重复绘制底色或点击区域。
- “开始探索”改为两枚较大四叶草在文字中央重叠承托，去除默认矩形按钮底；顶部导航和角落控件减少矩形底板，保留可触控区域与键盘焦点轮廓。
- 首页装饰收敛为偏侧重叠的少量大四叶草，保留中间留白与风感摆动；大四叶草右下增加随轮廓对齐的点阵投影。
- 侧栏增强近大远小、近疏远密的层次，高亮四叶草缩至约 105～115px；泡泡采用固定槽位，鼠标命中与文字变化分开，避免装饰跟随抖动。

本轮仍未进行 Safari 蒙版实测，实际文字对齐、图案投影和侧栏手感需通过已部署 demo 继续校准。

### 0.2.1 布局、点阵与转场节奏

- 主模型的背景四叶草改为每次访问随机分散，同一次访问的语言切换、窗口变化与模型切回不会重新洗牌。
- 暗角点阵加大间距，外缘圆点扩大并相接；四叶草投影的点由小到大连接成清楚的轮廓。
- 首页导航背景提高不透明度，侧栏远处文字也更清楚，保留字号与疏密层次。
- 探索转场缩短到约 1.6 秒；第二页的背景与内容在展开过程中共同淡入，并裁切在同一四叶草蒙版内。
- 小装饰约 2.6 秒生命周期，消失后休息 1.2 秒再重生，保留固定槽位。
- 第二模型继续作为占位，未新增文案或素材，保留原场景分布与较柔和的点阵配置。

### 0.3.0 向心暗角、观看模式与作者入口

- 首页点阵围绕画面中心形成环状排列，中心留白，向外圆点逐渐增大并衔接成完整暗角。
- 保留已确认的点阵层级、四叶草投影和转场节奏；第二模型的柔和点阵配置不变。
- 左下角改为带悬停与按下反馈的圆形图标按钮，进入观看模式时从播放按钮扩散圆形蒙版，逐步消去文字、装饰和视频处理层。
- 左上角改为圆形头像入口，悬停或键盘聚焦展开个人简介卡片，手机点击展开；头像、简介及联系链接有独立配置入口，供后续管理页接入。
- 当前头像与简介使用占位内容，没有虚构联系方式；本轮不新增管理后台或假保存流程。

### 0.3.1 边缘暗角与首屏加载

- 波点尺寸按四边距离渐变，收至画面外侧约 18% 的区域，中央 60% 宽与高的范围留白，保留向心排列与相连的大圆外缘。
- 在外部样式和主脚本加载前先显示黑底，视频开始播放后淡入画面，再执行原有文字与导航入场，避免先显示完整首页再隐藏的闪现。
- 视频加载较慢时使用封面继续开场；播放失败、减少动态效果或直接访问章节时提供可用页面。主脚本加载失败也会限时解除黑屏，禁用脚本仍可浏览基础内容。

### 0.3.2 宽椭圆波点暗角

- 按参考图改为覆盖大部分视窗的同心椭圆走势，圆点沿椭圆等距分布，尺寸变化集中在靠近画面边缘的区域，保留开阔的中心。
- 圆点保持正圆，向中央逐渐缩小至消失；外侧大圆衔接。参考图的红线仅用于确定轮廓，不显示在网页中。

### 0.3.3 倾斜点阵与稳定裁切

- 首页改为顺时针 8°、32px 间距的规则方格点阵；水平椭圆仅控制圆点大小，外侧最大半径 35px，圆点相连后形成连续暗角。旋转网格扩展到视窗之外，避免四角露空。
- 首页反色、探索转场和观看模式改用固定的同文档 SVG 裁切资源，动画仅更新路径属性，避免每帧替换 SVG 图片引发的解析与重绘问题；保留原有几何范围和高对比效果。
- Safari/WebKit 引擎检查与 iOS 真机验证分别记录，浏览器的手机视口不视为 iOS 真机复测。

### 0.3.4 方格点阵的尺寸与透明度羽化

- 主模型首页保留整体顺时针 8° 的正交等距网格；水平椭圆独立控制各圆的尺寸和透明度，越靠中心越小、越淡。
- 羽化范围按格距计算，保留至少三个格距的小点到连片过渡；桌面格距 32px，窄屏缩为 16px，以保留中央留白。最大圆按格距调整，避免过早重叠而只剩一圈轮廓。
- 用户已确认 iOS 闪烁不再复现；本轮保持 0.3.3 的稳定裁切实现，不修改蒙版或转场逻辑。
